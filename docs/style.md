# Соглашения о стилизации Microscope

Документ описывает правила работы с CSS, дизайн-токенами, единицами измерения, классами и визуальными состояниями проекта.

## Общие принципы

- Проект использует обычный CSS без UI-фреймворков и CSS-in-JS.
- `src/styles/mobile.css` — mobile-first: содержит все базовые правила и токены, применяемые на любом экране, без медиавыражений.
- `src/styles/desktop.css` — только переопределения для больших экранов внутри `@media (min-width: 621px)`.
- `mobile.css` импортируется из `src/main.tsx` и попадает в основной CSS-бандл, который загружается всегда.
- `desktop.css` собирается в отдельный минифицированный CSS-файл и подключается в `index.html` в конце `<body>` через `<link rel="stylesheet" media="(min-width: 621px)">` после основного бандла — на мобильных его правила не применяются и не блокируют рендер.
- Инлайн CSS в HTML отключён в `vite.config.js` (`build.assetsInlineLimit`), чтобы `desktop.css` оставался отдельным файлом; его минификацию выполняет плагин `minify-linked-css` (Vite не минифицирует CSS, подключённый через `<link>`).
- Повторяющиеся визуальные значения (цвета, отступы, радиусы, толщины границ, тени, размеры, `z-index`) выносятся в CSS-переменные в `:root`; литералы в правилах допустимы только для единичных значений.
- Совпадающие числом, но разные по смыслу значения — это разные токены (см. «Повторяющиеся значения»).
- В TSX не используются inline-стили для оформления. Исключение — конфигурация React Flow, где позиции и параметры рёбер задаются через JS API.
- В Preact используется атрибут `className`, а не `class`.
- Корневой контейнер — `body`: Preact монтируется прямо в него (`render(<App />, document.body)`), а стили оболочки приложения (flex-колонка, высота, фон) применяются напрямую к тегу `body`, без класса-обёртки. `App` рендерит фрагмент, поэтому шапка, граф и модалки — прямые дети `body`.
- Рабочая область графа обёрнута в тег `main` — это landmark для скринридеров. Чтобы обёртка не ломала flex-раскладку `body`, в `src/styles/mobile.css` для `main` задано `display: contents`.
- Селекторы строятся по BEM-подобной схеме:
  - `.block`
  - `.block__element`
  - `.block--modifier`

Примеры:

```css
.period-card
.period-card__title
.period-card--good
.period-card__insert
```

## Дизайн-токены

Все основные токены объявлены в `:root` и сгруппированы по смыслу:

1. **Layout** — размеры карточек, отступы, радиусы, размеры кнопок.
2. **Typography** — размеры шрифтов, line-height, letter-spacing.
3. **Palette** — цвета текста, поверхностей, границ, акцентов и состояний.
4. **Gradients** — готовые градиенты хороших и плохих карточек.
5. **RGB-компоненты** — для прозрачных цветов через `rgb(var(--...) / alpha)`.
6. **Shadows** — общие тени карточек, фокуса и кнопок.
7. **Animations** — длительности переходов, задержка тултипов, hover-scale, disabled-opacity.

Новые цвета, размеры и тени следует добавлять в `:root`, а не использовать напрямую в правилах.

### Повторяющиеся значения

- Если одно и то же визуальное значение встречается **в двух и более правилах**, для него нужно завести токен в `:root` и использовать `var(--...)`.
- Это касается не только цветов, но и толщин границ, радиусов, отступов, размеров шрифтов, теней, длительностей переходов и `z-index`.
- Если значения **совпадают числом, но имеют разный семантический смысл**, заводите **отдельные переменные** — пусть и с одинаковым значением. Например, радиус модального окна и радиус вложенной подложки или «gap между подписью и полем» и «отступ перед подсказкой» — это разные токены.
- Литерал в правиле оставляем только для действительно уникального, единичного значения, не имеющего смыслового повторения (например, `translate(-50%, 0.25rem)` у тултипа — это сдвиг анимации, а не отступ).
- Старайтесь не дублировать «магические» числа: если значение повторяется безымянно, дайте ему смысловое имя токена.

## Цвета

- Вне `:root` не должно быть литеральных HEX-цветов.
- Для прозрачности используются RGB-токены:

```css
background: rgb(var(--rgb-white) / 72%);
box-shadow: 0 10px 24px rgb(var(--rgb-card-shadow) / 10%);
```

- Семантические цвета good/bad:

```css
--color-good-border
--color-good-bg
--color-bad-border
--color-bad-bg
--color-good-dot
--color-good-dot-border
--color-bad-dot
```

- Маркеры состояния карточек (`.period-dot--good` / `.period-dot--bad`) — залитые круги: зелёный для good, красный для bad.

- Градиенты карточек задаются только через общие переменные:

```css
--gradient-good
--gradient-bad
```

Не следует задавать отдельные градиенты для периодов, событий и сцен: все они используют общие токены.

## Единицы измерения

### rem

Используется для:

- размеров шрифтов;
- паддингов и отступов;
- gap;
- радиусов;
- размеров кнопок и иконок;
- ширины модальных окон;
- компонентных размеров, которые должны масштабироваться вместе с корневым шрифтом.

Дробные значения — это точные доли `rem`: восьмые (1/8: `0.125`, `0.375`, `0.625`, `0.875`) и шестнадцатые (1/16: `0.0625`, `0.3125`, `0.4375`, `0.6875`, `0.8125`, `0.9375`). При корневом шрифте 16px они дают ровно целое число пикселей (2, 6, 10, 14 и 1, 5, 7, 11, 13, 15px соответственно) и одновременно масштабируются вместе с корневым шрифтом. Это не «лишняя точность»: не округляйте эти значения до 2 знаков — иначе появятся субпиксельные размеры (например, `0.6875rem` → `0.69rem` = 11.04px) и нарушится соответствие целым пикселям. Допустимая точность — до 4 знаков (восьмые и шестнадцатые доли `rem`).

### px

Используется для:

- геометрии React Flow:
  - `--event-card-width`;
  - `--scene-card-width`;
  - `--scene-gap`;
  - `--period-card-width`;
- толщины границ;
- теней и blur;
- медиазапроса;
- скрытых handles;
- служебных элементов вроде невидимых radio-инпутов.

Важно: `PERIOD_STEP` в `CardFlow.tsx` синхронизирован с `--period-card-width` и отступом между периодами. При изменении ширины периода нужно обновить и JS-шаг.

### Проценты, vh и dvh

- `100%` используется для растягивания карточек и контейнеров.
- Для высоты приложения задаётся fallback:

```css
height: 100vh;
height: 100dvh;
```

Эти же пары значений задают `height` и `min-height` тега `body`. Отдельный класс для корневого блока не нужен.

## Layout карточек

- Период — корневой React Flow-узел.
- События располагаются вертикально под периодом.
- Сцены располагаются справа от события и далее вертикально.
- Ширина периода рассчитывается через `calc()`:

```css
--period-card-width: calc(
	var(--event-card-width) + var(--scene-gap) + var(--scene-card-width)
);
```

- Карточка периода занимает всю ширину узла.
- Все события периода выровнены по одной вертикальной линии.
- Размеры и расположение кнопок задаются токенами `--icon-button-*` и `--action-button-*`.

## Кнопки действий

- Все кнопки имеют тултипы через `data-tooltip`.
- Для иконок используются UTF-8 символы:
  - `+⏳` — период;
  - `+⚡` — событие;
  - `+🎭` — сцена;
  - `✏️` — редактирование;
  - `🗑️` — удаление;
  - `🔄` — сброс;
  - `💾` — сохранение;
  - `📂` — импорт.
- Позиции кнопок:
  - редактирование — верхний левый угол карточки;
  - удаление — нижний левый угол;
  - добавление периода/события/сцены — справа или снизу в зависимости от типа.
- Hover-состояния используют общий токен `--hover-scale`.
- Disabled-состояния используют `--disabled-opacity`.

## Тултипы

Тултипы реализованы на CSS-псевдоэлементе `::after`:

```css
[data-tooltip]::after {
	content: attr(data-tooltip);
}
```

Правила:

- нативный `title` не используется;
- задержка появления — `1.5s` через `--tooltip-delay`;
- для кнопок в шапке и верхних углах карточек используется модификатор `tooltip-bottom`;
- подсказка не должна перекрываться соседними нодами: узел с наведением поднимается через `z-index`;
- текст подсказки должен кратко описывать действие кнопки;
- для доступности дублируется `aria-label`.

## Формы и модальные окна

- Общий контейнер модалки: `.modal-backdrop`.
- Общая панель формы: `.period-form`.
- Модификаторы:
  - `.period-form--initial` — стартовая форма;
  - `.period-form--confirm` — подтверждение действия.
- Поля формы используют классы:
  - `.period-form__field`;
  - `.period-form__types`;
  - `.type-option`;
  - `.type-option--active`;
  - `.period-form__actions`.
- Заблокированный тип периода отображается через `.period-form__locked-kind` без radio-кнопок.
- Ошибки показываются через `.period-form__error`.

## Состояния good/bad

Классы состояний формируются через модификаторы:

```text
period-card--good
period-card--bad
event-card--good
event-card--bad
scene-card--good
scene-card--bad
```

CSS-модификатор `good`/`bad` определяется через `cardKindModifier()` и не зависит от подписи типа:

- периоды: Расцвет / Упадок;
- события: Удача / Беда;
- сцены: Светлая / Мрачная.

## Z-index

Текущие уровни:

| Элемент | z-index |
| --- | ---: |
| Шапка | 2 |
| Кнопки добавления на карточке | 5 |
| Кнопки редактирования/удаления | 6 |
| Поднятый узел при hover | 20 |
| Модальные окна | 20 |
| Тултипы | 30 |

При добавлении новых слоёв следует переиспользовать эти уровни или явно документировать новый.

## Адаптивность

- Подход — mobile-first: базовые правила в `src/styles/mobile.css` рассчитаны на мобильные устройства; медиавыражений в нём нет.
- Десктопные переопределения — в `@media (min-width: 621px)` в `src/styles/desktop.css`; других правил там нет.
- При сборке `desktop.css` выводится отдельным CSS-файлом и подключается в конце `<body>` через `<link media="(min-width: 621px)">` после основного бандла.
- На узких экранах:
  - сетка начальных периодов становится одноколоночной;
  - модальные окна используют `max-width: calc(100vw - 1.5rem)`; при нехватке высоты `modal-backdrop` прокручивается по вертикали (`overflow-y: auto`), а `period-form` центрируется через `margin: auto`;
  - в стартовой модалке кнопка импорта перенесена в правый верхний угол (`position: absolute`), для неё зарезервирован `padding-top` у `.period-form--initial`.
  - радиокнопки типа карточки располагаются вертикально;
  - тултипы отключены (`display: none`), так как не работают на сенсорных экранах; на десктопе они показываются;
  - в шапке кнопки сброса/сохранения показываются только иконками и остаются в правом верхнем углу, а подсказки иконок идут одна под другой.
- На больших экранах подсказки иконок в шапке идут в одну строку, у кнопок действий возвращается текст.
- Текст в карточках переносится через `overflow-wrap: anywhere`.
- `body` имеет `overflow-x: hidden`, чтобы тултипы у краёв не создавали горизонтальный скролл.

## Доступность

- Все icon-only кнопки должны иметь `aria-label`.
- Интерактивные элементы должны иметь видимое focus-состояние.
- Для скрытых radio-инпутов сохраняется доступность через label.
- Тултипы работают при `:hover` и `:focus-visible`.
- Анимации короткие и не должны мешать взаимодействию.

## Чек-лист при добавлении стилей

1. Проверить, есть ли подходящий токен в `:root`.
2. Если значения повторяются — добавить переменную.
3. Использовать `rem` для типографики и компонентных отступов.
4. Оставить `px` для границ, теней и геометрии React Flow.
5. Не добавлять HEX-цвета вне `:root`.
6. Использовать BEM-подобные классы.
7. Добавить `data-tooltip` и `aria-label` для новых icon-only кнопок.
8. Проверить отображение при стандартном и увеличенном размере шрифта.
9. Проверить `npm run lint`, `npm run tsc` и `npm run build`.
