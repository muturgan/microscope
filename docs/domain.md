# Доменные правила Microscope

Документ описывает бизнес-логику и правила работы с карточками. Техническая архитектура — в [arch.md](./arch.md), формат хранения — в [storage.md](./storage.md).

## Иерархия карточек

```text
Период
└── События
    └── Сцены
```

- Периоды — верхнеуровневые карточки.
- Каждый период содержит список событий.
- Каждое событие содержит список сцен.
- Сцена не может существовать вне события, событие — вне периода.

## Типы карточек

Тип задаётся через `CardType`:

| Значение | Описание |
| --- | --- |
| `Period` | Период |
| `Event` | Событие |
| `Scene` | Сцена |

Тип карточки неизменяем после создания. При редактировании можно менять только название и `kind`.

## Состояние карточки

Состояние задаётся через `CardKind`:

| Значение | Внутреннее имя |
| --- | --- |
| Хорошее | `CardKind.Good` |
| Плохое | `CardKind.Bad` |

Пользователю отображаются разные подписи в зависимости от типа карточки:

| Тип | Хорошее | Плохое |
| --- | --- | --- |
| Период | Расцвет | Упадок |
| Событие | Удача | Беда |
| Сцена | Светлая | Мрачная |

CSS-модификаторы при этом остаются общими: `good` и `bad`.

## Создание сеттинга

При первом запуске или после сброса открывается модальное окно создания сеттинга.

Пользователь задаёт:

- название сеттинга;
- начальный период;
- конечный период.

Начальный период по умолчанию — хороший, конечный — плохой. Пользователь может изменить оба типа вручную. На этапе инициализации правило чередования не применяется: можно создать два хороших или два плохих периода.

Название сеттинга отображается в шапке и входит в сохраняемое состояние.

## Добавление периода

Период добавляется только между существующими периодами.

Ограничения:

- нельзя добавить период после последнего;
- новый период получает `kind`, противоположный предыдущему;
- после вставки в середину последующие периоды пересчитываются так, чтобы чередование сохранялось.

Пример:

```text
Расцвет → Упадок → [новый период] → Расцвет
```

Тип нового периода при создании заблокирован и показывается без radio-кнопок.

## Редактирование периода

При редактировании можно изменить название и `kind` периода.

Редактирование не запускает автоматический пересчёт соседних периодов. Если пользователь вручную нарушит чередование, приложение не исправляет это автоматически.

## События

- Событие всегда создаётся внутри конкретного периода.
- Добавить событие можно:
  - нижней кнопкой на карточке периода;
  - нижней кнопкой на карточке события — в тот же период.
- События одного периода располагаются вертикально под периодом.
- Событие можно отредактировать или удалить.

## Сцены

- Сцена всегда создаётся внутри конкретного события.
- Добавить сцену можно:
  - правой кнопкой на карточке события;
  - нижней кнопкой на карточке сцены — в то же событие.
- Первая сцена отображается справа от события.
- Последующие сцены располагаются под первой.
- Когда сцен становится больше, следующие события сдвигаются вниз.

## Удаление

Удаление всегда требует подтверждения.

Каскадные правила:

- удаление сцены удаляет только сцену;
- удаление события удаляет событие и все его сцены;
- удаление периода удаляет период, все его события и все сцены.

## Идентификаторы

Все карточки имеют глобально уникальные `id`.

`id` используются:

- как ключи React/Preact;
- для поиска карточки при редактировании и удалении;
- для React Flow-узлов;
- при валидации импортируемого состояния.

## Названия и примеры

- Интерфейс приложения на русском языке.
- Примеры названий используют фентези-викингскую стилистику.
- Примеры и подписи централизованы в `src/config/cardUi.ts`.
- При создании карточек placeholder выбирается случайно из набора примеров соответствующего типа.
