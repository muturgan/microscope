# Хранение и формат состояния

Документ описывает автосохранение, формат JSON, импорт/экспорт и валидацию состояния. Доменные правила — в [domain.md](./domain.md).

## localStorage

Состояние автоматически сохраняется в `localStorage` под ключом:

```text
microscope:cards-state:v1
```

### Когда сохраняется

- при изменении `cardsStore`;
- при изменении `settingNameStore`;
- перед `beforeunload`;
- при `pagehide`.

### Когда загружается

Состояние загружается при инициализации stores, до первого рендера приложения.

Если сохранения нет, оно повреждено или не проходит валидацию:

- запись удаляется;
- stores остаются пустыми;
- открывается модальное окно создания нового сеттинга.

### Пустое состояние

Если в состоянии нет периодов, запись из `localStorage` удаляется.

## Формат JSON

Экспортируемый файл имеет версию:

```json
{
  "version": 1,
  "settingName": "Сага о Ледяном Троне",
  "cards": []
}
```

Поля:

| Поле | Тип | Описание |
| --- | --- | --- |
| `version` | `1` | Версия формата состояния |
| `settingName` | `string` | Название сеттинга |
| `cards` | `IPeriodCard[]` | Массив периодов с вложенными событиями и сценами |

## Структура карточки в JSON

### Период

```json
{
  "id": "uuid",
  "title": "Название периода",
  "kind": 0,
  "type": 0,
  "events": []
}
```

### Событие

```json
{
  "id": "uuid",
  "title": "Название события",
  "kind": 1,
  "type": 1,
  "scenes": []
}
```

### Сцена

```json
{
  "id": "uuid",
  "title": "Название сцены",
  "kind": 0,
  "type": 2
}
```

## Числовые значения enum

В JSON сохраняются числовые значения `const enum`.

### CardType

| Значение | Число |
| --- | ---: |
| `Period` | 0 |
| `Event` | 1 |
| `Scene` | 2 |

### CardKind

| Значение | Число |
| --- | ---: |
| `Good` | 0 |
| `Bad` | 1 |

## Валидация импорта

При импорте проверяются:

- версия формата;
- наличие массива `cards`;
- тип каждой карточки;
- `kind` равен `0` или `1`;
- непустые `id` и `title`;
- массивы `events` и `scenes`;
- уникальность `id` среди всех карточек;
- минимум два периода.

При ошибке импорта состояние не изменяется, а пользователю показывается сообщение в модальном окне.

Если в старом файле отсутствует `settingName`, используется значение `Без названия`.

## Экспорт файла

Используется File System Access API:

```text
showSaveFilePicker
```

Пользователь выбирает расположение и имя файла. Имя по умолчанию формируется из названия сеттинга и получает расширение `.json`.

Если API недоступно, применяется fallback:

1. пользователь вводит имя файла;
2. файл скачивается через `Blob` и `URL.createObjectURL`.

## Импорт файла

Импорт выполняется через стандартный `<input type="file">` с фильтром JSON.

После успешной валидации:

- `settingNameStore` получает новое название;
- `cardsStore` полностью заменяется импортированными карточками;
- модальное окно создания нового сеттинга закрывается.

## Сброс состояния

Кнопка сброса в шапке:

- очищает `cardsStore`;
- очищает `settingNameStore`;
- удаляет запись из `localStorage`;
- открывает модальное окно создания нового сеттинга.

## Совместимость и миграции

При изменении схемы состояния:

1. увеличьте `version`;
2. добавьте миграцию или отдельный парсер для старой версии;
3. обновите этот документ;
4. проверьте импорт старого файла и загрузку старого `localStorage`.

Текущая версия поддерживает только `version: 1`.
